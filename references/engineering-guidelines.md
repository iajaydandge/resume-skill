# Engineering Resume Guidelines

> A resume is a 30-second elevator pitch on paper. Its job is to convince the hiring team to schedule an interview.

______________________________________________________________________

## General Principles

- Make it easy to read and skim — recruiters spend ~30 seconds on a resume
- Be specific and technical — generic job duties don't differentiate you
- Tailor for each application — address the job description directly
- Put the best, most relevant content first (top and left of the page)
- One page unless you have 10+ years of experience (1 page per decade)

______________________________________________________________________

## Formatting

- Single-column layout only
- No icons, images, or graphics
- Left-aligned text — never justified (causes inconsistent word spacing)
- No indenting sections or bullet points (bullets already create indentation)
- Modern readable font: Latin Modern / Computer Modern, Calibri, Bitstream Charter, Arial, Lato, or Helvetica
- Black font only — no grey; ensure printable in greyscale
- Minimum 10.5pt font size; avoid thin font weights
- Minimum 0.4 inch margins; minimum 1.07 line spacing
- Sufficient white space between sections and between each job/project
- Avoid excessive italics, bold, or ALL CAPS; if used, use each independently and sparingly — don't bold keywords within bullet points

### Dates

- Right-align dates to the right margin
- Use en dashes with spaces for ranges: Mar 2022 – Aug 2022 (not hyphens, not "to")
- Use Present (not Current, Now, Ongoing)
- Include month and year: March 2022 (not Winter 2022, not 9/2022)
- No specific days; full year only: 2023 (not '23)
- Month abbreviations (no periods): Jan, Feb, Mar, Apr, May, June, July, Aug, Sept, Oct, Nov, Dec
- Bullet points must not extend further right than the dates

## Section Order

| Situation | Order |
| ------------------------------------ | ---------------------------------------------------------- |
| Graduated + full-time job | Work Experience → Skills → Education |
| Student / new grad, some experience | Education → Work Experience → Skills |
| Student / new grad, limited work exp | Education → Work Experience → Projects → Skills |
| No technical work experience | Education → Projects → Work Experience → Skills |
| No work experience at all | Education → Projects → Volunteer/Extracurriculars → Skills |
| Senior engineer (10+ YoE) | Summary → Work Experience → Skills → Education |
| Career changer | Summary → Work Experience → Projects → Skills → Education |

Do not include a summary unless you are senior/staff level, making a career change, or returning after a gap. Do not include a references section.

## Contact Information

- Include: name, email, GitHub (if populated), portfolio (if current)
- Optional: phone, LinkedIn (rarely clicked by recruiters)
- Include near your name if relevant: security clearance level, citizenship or visa status
- Omit: physical address, ZIP code, city/state (unless applying locally), country code (+1)
- Write URLs as plain text — no hyperlink masking: github.com/username not a link labeled "GitHub"
- No prefixes: no "Email:", "Phone:", "GitHub:"
- Don't include https://www. in URLs
- Don't underline, italicize, or color URLs
- Use Gmail or Outlook — not AOL, Hotmail, or Yahoo
- Don't link GitHub if it has no repos with good READMEs

## Work Experience

- Section name: Work Experience or Experience — not "Professional Experience", "Employment History", etc.
- Paid work only (research experience counts)
- Label internships as internships; label contract roles as contract
- Order by relevance and impressiveness — best first
- Focus on accomplishments, not job duties
- Add context: explain what you did and how you solved problems, not just what tools you used
- Tailor bullet points to address the job description

## Bullet Points

- 1–2 lines each; aim for one sentence
- Begin with a strong past-tense action verb
- No personal pronouns (I, we, my, our)
- No periods at the end
- Use digits: 8 not eight
- Avoid apostrophes, ampersands (&), slashes (/)
- Avoid adjectives and adverbs: excellent, innovative, meticulously, successfully
- Order from most relevant/impressive to least
- Avoid sub-bullets — they clutter and make the resume harder to read
- Don't spill to the next line with only 1–4 words — rewrite or trim

### Frameworks

Use STAR (Situation, Task, Action, Result), CAR (Challenge, Action, Result), or XYZ (Accomplished X as measured by Y by doing Z). If you can quantify results, move the metric toward the start of the bullet.

### Strong action verbs

analyzed, architected, automated, built, created, decreased, designed, developed, implemented, improved, integrated, optimized, published, reduced, refactored, validated, tested, modeled, simulated, characterized, fabricated, assembled, calibrated, diagnosed, prototyped

Note: "Led" is the past tense of "lead"

### Weak verbs to avoid

aided, assisted, coded, collaborated, communicated, executed, exposed to, gained experience, helped, participated, programmed, ran, used, utilized, worked on

### Superfluous verbs to avoid

amplified, conceptualized, crafted, elevated, employed, engaged, engineered, enhanced, ensured, fostered, honed, innovated, mastered, orchestrated, perfected, pioneered, revolutionized, spearheaded, transformed

### Frequently misused

- utilize — almost always just means "use"; avoid it
- leverage — usually jargon for "use"
- enhance — often confused with "improve" (enhance = add features; improve = make better)

### Writer's block prompts

What did I do?

- Did I solve a problem?
- Did I work independently or on a team? How big was the team?

How did I do it?

- Why did I do it this specific way?
- What tools/software/standards did I use?
- Did I validate or test my work? How did that affect the final result?

What were the results?

- Did I deliver on time or under budget?
- Did the design/solution work as intended?
- What went wrong? What did I learn?

### Integration over parts list

It matters less what specific components you used and more how you integrated them to accomplish the goal.

Instead of: "Used a Raspberry Pi and stepper motor to complete task X"
Write: "Developed Python control software interfacing with stepper motors via GPIO to achieve ±0.5° positioning accuracy for task X"

### Your resume is not your job description

Simply listing job duties = what everyone else wrote. Show accomplishments, tangible metrics, and the engineering judgment behind your choices — not just the tools used.

### Handling sensitive or classified content

Talk about the technologies and methods without revealing forbidden details. Instead of naming the specific system, describe the category: "Developed C++ software for evaluating aircraft subsystems on [hardware standard]-based test bench." Shed enough light to be interesting without crossing lines.

### Sample bullet patterns (software)

- Improved X by Y% by refactoring Z component to use [approach]
- Reduced [metric] from A to B by implementing [solution] in [language/framework]
- Designed and shipped [feature] serving N users, improving [outcome]
- Automated [manual process] using [tool/script], saving X hours/week
- Identified and resolved root cause of [bug/performance issue], reducing [error rate/latency] by X%

### Sample bullet patterns (mechanical/hardware)

- Designed [component] using [software/analysis], achieving [performance metric] within [constraint]
- Reduced [weight/cost/lead time] by X% through [design change or process improvement]
- Validated [system/design] via [testing method], confirming compliance with [standard/spec]
- Developed test fixture for [component], enabling [outcome] and reducing test time by X%
- Performed FEA/CFD analysis on [component], iterating design to achieve [metric]; validated with hand calculations

## Education

- Reverse chronological (Master's above Bachelor's)
- Graduation date only — no start date, no date range
  - Current student: Expected May 2025
  - Graduated: May 2021 or just 2021
- GPA: include if ≥ 3.75, two decimal places; remove once you have full-time work experience
- Degree: Bachelor of Science, Master of Science (no apostrophe-s)
- Omit: high school, schools without a degree, coursework (unless extremely specialized), awards (unless Rhodes/Fulbright-level)
- Include D1 or competitive sports

______________________________________________________________________

## Skills

- Section name: Skills — not "Technical Skills", "Relevant Skills"
- 3 lines or fewer, single column, comma-separated
- Group into relevant categories: Languages, Technologies, Tools, etc.
- Capitalize correctly: SolidWorks, CATIA V5, LabVIEW
- Write "C, C++" not "C/C++"
- Write "Git" not "GitHub", "GitLab", or "Bitbucket"
- Omit: soft skills, operating systems, IDEs, skills you can't speak to in an interview

______________________________________________________________________

## Projects

- Section name: Projects — not "Academic Projects", "Personal Projects", etc.
- Personal, extracurricular, and hobbyist projects — not work projects
- Don't use the word "project" in the title
- No need to label "Personal" or "Academic" beside the title
- Include a GitHub or portfolio link if the repo is maintained and has a good README
- Bullet points, not paragraphs; best first

## Common Mistakes Checklist

- [ ] Multi-column layout → single column only
- [ ] Icons, images, graphics → remove
- [ ] Justified text → left-align
- [ ] Extra indentation on bullets/sections → remove
- [ ] Grey or thin font → black, readable weight
- [ ] Bold keywords within bullets → remove
- [ ] Bullets ending in periods → remove periods
- [ ] Personal pronouns → remove
- [ ] Weak verbs (utilized, assisted, worked on) → replace
- [ ] Bullet spills to next line with 1–4 words → rewrite/trim
- [ ] Two pages without 10+ YoE → trim to one page
- [ ] High school listed → remove
- [ ] Soft skills in skills section → remove
- [ ] Hyphens in date ranges → replace with en dashes (–)
- [ ] Dates not right-aligned → fix
- [ ] "Current" or "Ongoing" → replace with "Present"
- [ ] Season or semester dates → replace with month/year
- [ ] Abbreviated years ('23) → full year (2023)
- [ ] Summary included without seniority/career-change context → remove
