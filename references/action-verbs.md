# Action Verbs Guide for Engineering Resumes

Every bullet point must begin with a strong, specific, past-tense action verb. A recruiter skimming in 30 seconds relies on the initial verb to judge the depth of your technical contribution.

______________________________________________________________________

## Approved High-Impact Action Verbs

Categorized by technical focus:

### Software Architecture & Systems

- `architected` — designed high-level system structures, contracts, or microservices
- `designed` — drafted architectures, state machines, API specs, schemas
- `developed` — wrote and delivered full modules, features, or pipelines
- `implemented` — translated specs or algorithms into production code
- `integrated` — connected distinct systems, APIs, or protocols
- `refactored` — overhauled codebases to eliminate tech debt or increase modularity
- `built` — constructed end-to-end applications or utilities from scratch

### Optimization & Infrastructure

- `optimized` — improved speed, memory, throughput, or resource consumption
- `reduced` — cut latency, error rates, costs, test times, or package sizes
- `decreased` — lowered resource footprint or cycle time
- `automated` — replaced manual interventions with scripts, CI/CD, or pipelines

### Quality, Verification & Analysis

- `analyzed` — performed profiler analysis, log inspection, bottleneck discovery
- `tested` — executed unit, integration, stress, or regression suites
- `validated` — verified system correctness against specs or benchmarks
- `diagnosed` — identified root causes of anomalies, deadlocks, or regressions
- `published` — released open-source packages, whitepapers, or technical specs

### Hardware, Embedded & Physical Engineering

- `modeled` — created mathematical or CAD models
- `simulated` — ran SPICE, FEA, CFD, or Monte Carlo simulations
- `characterized` — measured hardware physical, electrical, or thermal parameters
- `fabricated` — manufactured physical prototypes or PCB boards
- `assembled` — constructed mechanical or electrical hardware assemblies
- `calibrated` — aligned sensors, instruments, or actuators to standards
- `prototyped` — engineered working proof-of-concept hardware/firmware

*(Note: If describing past leadership, use `Led` — the past tense of `lead`).*

## Weak Verbs to Avoid & Direct Replacements

Weak verbs make you sound like a passive spectator rather than an active engineer.

| Weak Verb | Why It Fails | Replacement Alternatives |
| ---------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------- |
| `assisted` / `aided` / `helped` | Signals you only watched or did menial tasks | `implemented`, `built`, `integrated`, `tested`, `automated` |
| `coded` / `programmed` | Stating the obvious; lacks engineering intent | `developed`, `architected`, `implemented`, `refactored` |
| `collaborated` / `communicated` | Soft skill filler; resumes should show technical actions | `integrated`, `partnered with [Team] to design`, `aligned` |
| `executed` | Generic task completion | `automated`, `deployed`, `implemented`, `validated` |
| `worked on` / `participated` | Vague; obscures what *you* actually did | `built`, `optimized`, `designed`, `diagnosed` |
| `used` / `utilized` | Focuses on the tool, not the engineering accomplishment | Focus on the action: `developed ... using`, `engineered ... via` |
| `gained experience` / `exposed to` | Sounds like a passive student | `analyzed`, `researched`, `modeled`, `deployed` |
| `ran` | Mundane execution | `orchestrated`, `benchmarked`, `simulated`, `executed` |

## Superfluous Buzzwords to Avoid

Avoid inflated marketing buzzwords that lack concrete engineering meaning:

- `amplified`
- `conceptualized`
- `crafted`
- `elevated`
- `employed`
- `engaged`
- `engineered` (vague when used as a verb; prefer `designed` or `developed`)
- `enhanced` (often confused with `improved`; enhance = add cosmetic features)
- `ensured`
- `fostered`
- `honed`
- `innovated`
- `mastered`
- `orchestrated`
- `perfected`
- `pioneered`
- `revolutionized`
- `spearheaded`
- `transformed`

*Rule: If a word sounds like it belongs in a press release rather than a technical design document, cut it.*

## Frequently Misused Verbs

1. **`utilize`**:

   - *Problem*: Almost always pretentious jargon for "use".
   - *Fix*: Avoid completely. Focus on what was built or solved, referencing the tool as context.
   - *Bad*: "Utilized Docker to deploy microservices"
   - *Good*: "Automated microservice deployments by building Docker containerization pipelines"

1. **`leverage`**:

   - *Problem*: Financial jargon converted into vague corporate filler.
   - *Fix*: Replace with the specific technical mechanism.
   - *Bad*: "Leveraged Redis to cache user sessions"
   - *Good*: "Reduced database read latency by 65% by implementing Redis in-memory session caching"

1. **`enhance` vs `improve`**:

   - *Distinction*: `enhance` means to add features or augment; `improve` means to make existing metrics better.
   - *Rule*: When metrics or performance increase, use `improved`, `reduced`, or `optimized`, not `enhanced`.
